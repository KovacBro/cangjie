# 字码协议 v1.0

本协议定义"密码本块"的格式、编码/解码规则、以及字码在什么场合可以出现。
实现见 `cangjie/codec.py`、`cangjie/state.py::Dictionary.block()`。

---

## 1. 密码本块（Codebook Block）

### 1.1 语法

```
<仓颉v{版本} pool={载体预设} n={条目数}>
{字}={原短语}
{字}={原短语}
...
</仓颉>
```

| 字段 | 约束 |
|---|---|
| `v` | 字典版本号，与 `dict.json.version` 一致；不复用旧号 |
| `pool` | `auto` / `sym` / `han` / `forge` |
| `n` | 条目数，用于自校验（块内行数必须等于 n） |
| `字` | **恰好一个 Unicode 字符**（码位可以是 BMP 符号、汉字或 PUA） |
| `=` | 唯一分隔符；原短语内不得含 `=`（入库前校验） |

### 1.2 三种输出格式

| `--format` | 用途 | 样例 |
|---|---|---|
| `compact`（默认） | 注入上下文，最省 token | `▀=向量检索` |
| `md` | 人类阅读 / 写进报表 | `\| ▀ \| 向量检索 \| 事 \| 48 \|` |
| `json` | 程序消费 | `{"v":1,"pool":"auto","d":{"▀":"向量检索"}}` |

### 1.3 放置位置

必须放在**提示词的最前面**（系统提示之后、正文之前），且跨轮次**逐字节稳定**：

```
[系统提示]
[密码本块]        ← 稳定前缀，只追加，不改动
[工作记忆包]
[最近 k 轮对话]
[本轮输入]
```

理由：多数厂商的 prefix cache 要求前缀完全一致。把密码本放最前，它被缓存后价格为 1/10；
一旦每轮改动，缓存全失效，压缩反而赔钱。

## 2. 编码规则

### R1 最长优先

同一位置可匹配多个短语时取最长：

```
表: 向量→▲, 向量检索→△
入: 向量检索
出: △          （不是 ▲检索）
```

### R2 保护区（默认开启）

以下片段**不参与短语替换**，原样保留：

| 类型 | 识别方式 |
|---|---|
| 围栏代码块 | ```` ``` ... ``` ```` / `~~~ ... ~~~` |
| 行内代码 | `` `...` `` |
| URL | `http(s)://` / `ftp://` |
| Windows 路径 | `C:\...` |
| 相对路径 | `./a/b`、`../x/y` |

保护区内的短语仍会被"统计"（`count`），但不会被替换；
若某短语**只**出现在保护区，`skip_code_only` 会把它排除出字典（压不到就不该占位）。

### R3 转义

原文若恰好包含某个载体字，必须转义，否则解码会误还原：

| 原文 | 编码后 | 解码后 |
|---|---|---|
| `▀`（字面） | `\▀` | `▀` |
| `\▀`（反斜杠+字面字） | `\\▀` | `\▀` |
| `C:\Users` | `C:\Users`（不动） | `C:\Users` |

规则：只有"反斜杠紧跟载体字"的组合才参与转义，普通反斜杠完全不动。
因此 Windows 路径、正则、LaTeX 都不受影响。

### R4 不增反减

编码器只做"变短"的替换。`cost(短语) - cost(载体) < min_gain` 的短语在上游就被丢弃，
不会进入字典（见 `carriers.CarrierPool.pick`）。

### R5 可逆性

对任意合法 UTF-8 文本 `x`：`decode(encode(x)) == x`。

`cangjie doctor` 用四类样本每次校验：
纯中文 / 代码块+反斜杠路径 / 数字混排 / 中英混排。

## 3. 解码

单趟字符扫描 + 转义状态机，O(n)。

```
for ch in text:
    if ch == '\\' and 下一个是载体字:  输出字面字, 跳过 2
    elif ch == '\\' and 下一个是 '\\' 且再下一个是载体字: 输出 '\' + 字面字, 跳过 3
    elif ch in 字典:  输出原短语
    else: 输出 ch
```

未出现在字典里的字符一律原样透传（可解码"部分压缩"的混合文本）。

## 4. 输出闸门

| 场合 | 字码 |
|---|---|
| 模型内部推理 / 草稿 | ✅ |
| 工具输出（`cangjie run`） | ✅（附还原提示） |
| 工作记忆包 / 摘要 / 账本 | ✅ |
| 给用户的最终回答 | ❌ |
| 交付文件（代码/文档/配置） | ❌ |
| commit / PR / 对外消息 | ❌ |
| 多人共享文档 | ❌ |

**判定口诀**：只要这段文字可能被别人看到，就必须先 `expand`。

## 5. 版本演进

| 变更 | 处理方式 |
|---|---|
| 新增条目 | `version` +1，新条目追加到密码本末尾（保护前缀） |
| 删除条目 | `version` +1；旧包必须重建，否则出现"未知字"（解码时原样透传，不报错） |
| 更换载体预设 | `version` +1 并全量重分配（已命中过的条目会损失历史统计） |
| 升级协议 | `v` 主版本号变更，旧实现拒绝解码 |

**兼容性约定**：解码器遇到不认识的载体字时**不报错、原样输出**——
宁可留下一个怪字符，也不能中断整段文本。
