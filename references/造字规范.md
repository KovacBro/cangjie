# 造字规范 v1.0

## 1. 为什么要造字

字码需要一个"载体"。载体有三种来源：

| 来源 | 单价 | 显示 | 数量 | 适用 |
|---|---|---|---|---|
| 现成符号（■▲◆◇） | **1 tok** | 任何设备 | ~数百 | ✅ 默认 |
| 现成汉字（常用字） | 2 tok | 任何设备 | 上千 | 追求"像真字" |
| 自造字（PUA） | 2.4–3 tok | **需装字体** | 6400 | 需要独一无二的形态 |

自造字**不省 token**（比符号贵一倍多），它的价值是：形态可辨识、语义可读、身份独有——"仓颉造字"的本意。

## 2. 构字法（形声）

```
合体字 = 左义符（形旁，表义类） + 右声符（表音/取首字）
```

| 义符 | 语义场 | 关键词示例 |
|---|---|---|
| 数 | 数据/指标 | 数据 统计 指标 token score |
| 错 | 错误/异常 | 错误 异常 超时 debug error |
| 令 | 规则/策略 | 规则 策略 校验 protocol |
| 器 | 组件/框架 | 组件 引擎 模块 sdk |
| 网 | 网络/接口 | 接口 请求 路由 api |
| 人 | 用户/权限 | 用户 角色 登录 auth |
| 时 | 时间/周期 | 定时 延迟 周期 timeout |
| 值 | 配置/参数 | 配置 参数 阈值 config |
| 图 | 图形/界面 | 界面 布局 渲染 ui |
| 文 | 文件/文档 | 文件 文档 路径 file |
| 言 | 语言/日志 | 提示 注释 日志 log |
| 事 | 任务/流程（兜底） | 任务 流程 事件 task |

分类算法：命中关键词的**字符总长**最大者胜；同分按表序（具体领域优先，言/事垫底）。
见 `cangjie/glyphs.py::classify`。

## 3. 布局

| 布局 | 条件 | 说明 |
|---|---|---|
| `lr` 左右 | 默认 | 左义符占 45%，右声符占 55% |
| `tb` 上下 | 声符是宽笔画字（一/大/日/目/田…） | 上义符下声符 |

## 4. 两种落地产物

### 4.1 SVG 图样（零依赖）

`assets/glyphs-preview.html`：每个字一个卡片，显示
`码位 / 原意 / 义符·声符 / 出现次数 / 原价→现价`。

用 `<text textLength>` 把两个字压进一个方框，视觉上就是"合体"。任何浏览器可看，不需要装字体。

### 4.2 TTF 字体（可选）

```bash
cangjie forge [--font C:/Windows/Fonts/simsun.ttc] [--family CangjieCompress]
```

实现要点（`glyphforge.py`）：

1. 读源字体 `TTFont(src, fontNumber=0)`，取 `glyphSet` / `getBestCmap()` / `unitsPerEm`；
2. 用 `BoundsPen` 量出组件包围盒，算缩放平移，把两个字分别塞进左/右半格；
3. `TransformPen` 把轮廓画进 `TTGlyphPen`；
4. `FontBuilder` 组装 `glyphOrder / cmap / glyf / hmtx / hhea / name / OS2 / post / maxp`；
5. 码位从 **U+E000** 起顺序分配。

产物：`assets/CangjieCompress.ttf`（实测 upem 2048，每字轮廓正常，`cmap` 映射正确）。

**注意**：PUA 字在未装字体的环境里显示为方框（tofu）。
所以**绝对不要**把 PUA 字放进对外输出——这也违反字码协议的输出闸门。

## 5. 命名与码位分配

| 项 | 规则 |
|---|---|
| 字体家族名 | `CangjieCompress`（可 `--family` 覆盖） |
| 码位区间 | PUA BMP：U+E000–U+F8FF（6400 个，够 128 条字典用 50 轮不撞） |
| 字形名 | `cj0000`, `cj0001`, … |
| 顺序 | 与 `dict.json` 条目顺序一致（稳定，便于比对） |

## 6. 局限

- 源字体缺字时该条目跳过，`forge` 会打印 `missed` 列表；
- 只做轮廓拼接，不做笔画避让——复杂字可能显得拥挤；
- 不生成 hinting，小字号可能糊；
- 字体未签名，部分系统会提示"未知字体"。
